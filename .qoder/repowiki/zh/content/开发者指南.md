## 代码规范

本项目遵循清晰的编码风格和命名约定，以确保代码的一致性和可维护性。

### Python 编码规范

后端使用 Python 3.11+ 和 FastAPI 框架，需遵守以下规范：

- **缩进与格式**：使用 4 个空格进行缩进，遵循 PEP 8 标准。
- **命名约定**：
  - 函数和变量使用 `snake_case`
  - 类名使用 `PascalCase`
  - 常量使用 `UPPER_CASE`
- **类型注解**：所有函数必须包含类型提示（Type Hints），提高代码可读性和 IDE 支持。
- **模块职责分离**：
  - 路由定义在 `backend/src/routes/` 目录下
  - 业务逻辑实现在 `backend/src/service/` 目录下
  - 工具函数封装在 `backend/src/utils/` 目录中
- **文档字符串**：所有公共函数和类必须包含 Google 风格的 docstring，说明功能、参数、返回值和异常。

### JavaScript/React 编码规范

前端基于 React 18.3 和 Vite 构建，需遵守以下规范：

- **缩进与格式**：使用 2 个空格进行缩进。
- **命名约定**：
  - 组件名使用 `PascalCase`
  - 变量和函数使用 `camelCase`
  - 文件名与组件名保持一致
- **组件设计**：优先使用函数式组件和 React Hooks，避免不必要的类组件。
- **样式管理**：CSS 模块化，避免全局样式污染。
- **国际化支持**：文本内容通过 `i18next` 进行管理，不得硬编码中文或英文字符串。

### 提交信息规范

所有 Git 提交信息必须遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范，格式如下：

```
<type>: <description>
```

支持的类型包括：
- `feat`：新增功能
- `fix`：修复缺陷
- `docs`：文档更新
- `style`：代码格式调整（不影响逻辑）
- `refactor`：代码重构
- `test`：测试相关更改
- `chore`：构建或工具链更新

## 测试策略

项目采用自动化测试确保代码质量和稳定性，涵盖单元测试、集成测试和覆盖率监控。

### 单元测试结构

测试文件组织与源码结构对应，位于以下目录：
- 后端测试：`backend/tests/`
- 自动化测试：`auto_test/`

每个模块应有对应的测试文件，命名规则为 `test_<module>.py`，例如 `test_auth.py` 测试 `auth.py` 模块。

### 运行测试

#### 后端测试

使用 `pytest` 执行测试并生成覆盖率报告：

```bash
# 运行所有测试
cd backend
python -m pytest

# 运行测试并生成覆盖率报告（HTML + XML）
python -m pytest --cov=src --cov-report=html:coverage_html --cov-report=xml:coverage.xml
```

也可通过批处理脚本一键运行：

```bash
# Windows
run_tests_coverage.bat
```

该脚本会自动生成 HTML 覆盖率报告（位于 `coverage_html/index.html`）和 XML 报告（用于 CI/CD 集成）。

#### 前端测试与 Lint

前端项目配置了 ESLint 进行代码质量检查：

```bash
cd frontend
npm run lint
```

### 测试覆盖率目标

根据 `feature.md` 中的技术债务要求，**单元测试覆盖率目标为 80% 以上**。`.coveragerc` 配置文件已排除测试目录和虚拟环境，专注于核心源码（`src/`）的覆盖分析。

```ini
[run]
branch = True
source = src

[report]
show_missing = True
omit =
    tests/*
    venv/*
    **/__pycache__/*
```

开发者在新增功能或修复缺陷时，必须同步更新或添加测试用例，确保覆盖率不下降。

## 贡献流程

我们欢迎所有开发者参与项目贡献。请遵循以下标准流程提交代码。

### 贡献步骤

1. **Fork 仓库**：在 GitHub 上 Fork 本项目到个人账户。
2. **克隆代码**：
   ```bash
   git clone <your-fork-url>
   cd backtrader
   ```
3. **创建特性分支**：
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. **编写代码与测试**：
   - 遵循代码规范
   - 添加必要的单元测试
   - 确保测试通过且覆盖率达标
5. **提交更改**：
   ```bash
   git add .
   git commit -m "feat: add your feature"
   ```
6. **推送分支**：
   ```bash
   git push origin feature/your-feature-name
   ```
7. **创建 Pull Request**：
   - 访问 GitHub 仓库页面
   - 点击 "Compare & pull request"
   - 填写 PR 描述，说明变更内容和关联 issue（如有）

### Pull Request 要求

- 清晰描述功能或修复内容
- 如涉及 UI 变更，请附上截图
- 如修改配置或数据库结构，需说明迁移步骤
- 确保 CI 测试通过

## 调试技巧

高效调试是开发过程中的关键环节。以下是推荐的调试方法。

### 日志使用

后端使用标准日志输出，可通过以下方式查看：

```bash
# 启动后端服务查看实时日志
cd backend
python main.py
```

关键模块日志输出点：
- `strategy_sandbox.py`：策略加载失败时的详细错误
- `websocket_manager.py`：WebSocket 连接状态
- `live_engine.py`：实盘交易执行流程

### 断点调试

推荐使用 IDE（如 PyCharm、VS Code）进行断点调试：
- 后端：在 `main.py` 或具体服务模块中设置断点
- 前端：在 React 组件或 `services/api.js` 中设置断点

确保 `.env` 配置正确，以便连接真实数据源或模拟环境。

### 前后端联调

前端通过 Vite 配置代理与后端通信：

```js
// vite.config.js
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8000',
        changeOrigin: true,
      },
      '/images': {
        target: 'http://127.0.0.1:8000',
        changeOrigin: true,
      },
    }
  }
})
```

启动开发服务器即可实现无缝联调：
```bash
# 前端
npm run dev
# 后端
python main.py
```

## 技术债务清理

根据 `feature.md` 中列出的技术债务，鼓励开发者参与以下改进工作，以提升项目整体质量。

### 统一错误处理机制

当前各模块错误处理分散，建议实现全局异常处理器，统一返回标准化错误码和消息。可在 `backend/src/routes/` 中引入中间件捕获未处理异常。

### API 响应格式标准化

确保所有 API 接口返回一致的响应结构，例如：
```json
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}
```
或错误时：
```json
{
  "success": false,
  "error": { "code": "invalid_param", "message": "参数无效" }
}
```

### 单元测试覆盖率提升

当前测试覆盖不均，部分核心模块（如 `live_engine.py`、`risk_manager.py`）缺乏充分测试。贡献者可优先为这些模块编写测试用例，逐步达成 80%+ 覆盖率目标。

### 性能测试

建议建立性能基准测试，监控关键路径性能：
- 回测执行速度（不同周期、标的）
- API 响应时间（P95/P99）
- WebSocket 消息延迟

可使用 `pytest-benchmark` 或独立脚本进行压测。

补充缺失的 API 文档、用户手册和部署指南，提升新开发者上手效率。
