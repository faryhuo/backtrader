## 安装与部署问题

### 依赖安装失败

当执行 `pip install -r requirements.txt` 时，可能会遇到依赖安装失败的问题，尤其是在网络受限的环境中。

**解决方案：**
1. 使用国内镜像源加速安装：
   ```bash
   pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
   ```
2. 如果使用 Docker 部署，Dockerfile 已配置阿里云镜像源以加速下载。
3. 检查 `requirements.txt` 中的版本约束，避免冲突。例如，`pycares<5.0.0` 是为了避免与 `aiodns` 的兼容性问题。

**Section sources**
- [requirements.txt](file://backend/requirements.txt)
- [Dockerfile](file://Dockerfile)

### 端口占用

默认情况下，应用在 `0.0.0.0:8000` 上启动。如果该端口已被占用，服务将无法启动。

**解决方案：**
1. 修改 `.env` 文件中的 `PORT` 变量：
   ```
   PORT=8001
   ```
2. 在 `docker-compose.yml` 中修改端口映射：
   ```yaml
   ports:
     - "8021:8000"
   ```
3. 使用命令行查找并终止占用端口的进程：
   ```bash
   lsof -i :8000
   kill -9 <PID>
   ```

### Docker构建错误

Docker 构建过程中可能出现编译错误或依赖冲突。

**解决方案：**
1. Dockerfile 采用多阶段构建，第一阶段安装编译依赖，第二阶段仅安装运行时依赖，以减少镜像大小和构建复杂性。
2. 如果构建失败，检查 `MAX_JOBS=1` 是否导致编译过慢，可尝试增加并行任务数。
3. 确保 `.env.prod` 文件存在于 `backend/` 目录下，否则构建会失败。

## 运行时问题

### 回测失败

回测失败通常由策略代码错误、数据源问题或配置不当引起。

**诊断步骤：**
1. 检查策略文件是否存在于 `backend/src/strategy/` 目录下。
2. 验证 `broker_config.json` 中的 `supported_timeframes` 是否包含所选时间框架。
3. 确保 `symbol` 格式正确，如 `BTC/USDT`。

### 实盘交易会话无法启动

实盘交易会话启动失败可能由于配置禁用、凭证缺失或交易所连接问题。

**诊断步骤：**
1. 确认 `.env` 文件中 `LIVE_TRADING_ENABLED=true`。
2. 检查 `broker_config.json` 中目标交易所是否启用。
3. 验证 API 凭证是否正确配置，可通过 `Settings` UI 或环境变量设置。

**解决方案：**
- 使用 `credential_validator.py` 测试凭证有效性：
  ```python
  from src.utils.credential_validator import validate_ccxt_credentials
  is_valid, msg = validate_ccxt_credentials("binance", "live", "your_api_key", "your_secret")
  ```

### WebSocket连接中断

WebSocket 连接中断可能由网络问题、服务器重启或客户端超时引起。

**诊断策略：**
1. 检查服务器日志中是否有 `WebSocket disconnected` 记录。
2. 确认客户端是否定期发送心跳包。
3. 验证 `trading_settings` 中的 `reconnect_on_disconnect` 是否启用。

**解决方案：**
- 增加重试次数：`max_reconnect_attempts=10`
- 检查防火墙或代理是否阻止 WebSocket 连接。

### API调用返回错误

API 调用返回错误码（如 400、403、500）时，需根据错误类型进行排查。

**常见错误：**
- **400 Bad Request**: 请求参数无效，检查 `StartLiveRequest` 模型的字段。
- **403 Forbidden**: 权限不足，确认 `LIVE_TRADING_ENABLED` 和 API 密钥权限。
- **500 Internal Error**: 服务器内部错误，查看日志获取详细信息。

**诊断步骤：**
1. 检查 `live_routes.py` 中的异常处理逻辑。
2. 确认 `user_id` 是否正确传递用于凭证查找。

**Section sources**

## 日志分析与错误诊断

### 查看和分析日志

日志是诊断问题的关键。`main.py` 配置了日志记录器，输出格式包含时间、模块名、级别和消息。

**日志路径：**
- 默认输出到控制台。
- 可通过 `LOG_LEVEL` 环境变量调整日志级别（INFO、DEBUG、ERROR）。

**关键日志信息：**
- 服务器启动：`Starting server on {host}:{port}`
- 会话创建：`Created session {session_id}: {strategy_name} on {symbol}`
- 错误信息：`Failed to start live trading: {e}`

**建议：**
- 在生产环境中将日志重定向到文件或集中式日志系统。
- 使用 `logging.basicConfig` 配置文件处理器。

## 外部服务集成问题

### 网络连接测试

与交易所 API 或 OpenAI 的连接问题通常由网络限制引起。

**测试方法：**
1. 使用 `requests` 测试 OpenAI 连接：
   ```python
   import requests
   response = requests.get("https://api.openai.com/v1/models", headers={"Authorization": "Bearer YOUR_KEY"})
   ```
2. 对于交易所，使用 `ccxt` 库测试连接：
   ```python
   import ccxt
   exchange = ccxt.binance({'apiKey': 'YOUR_KEY', 'secret': 'YOUR_SECRET'})
   balance = exchange.fetch_balance()
   ```

### 凭证验证

凭证错误是集成失败的常见原因。

**验证步骤：**
1. 使用 `ConfigManager` 获取凭证：
   ```python
   from src.config.config_manager import ConfigManager
   config_manager = ConfigManager(user_id="user123")
   openai_config = config_manager.get_openai_config()
   ```
2. 使用 `credential_validator.py` 进行测试：
   ```python
   is_valid, msg = validate_openai_key("sk-...", "https://api.openai.com/v1")
   ```

**凭证优先级：**
1. 数据库（用户特定，加密存储）
2. 环境变量（`.env` 文件）
3. 默认值（硬编码回退）

## 常见错误代码与解决方案

| 错误代码 | 错误信息 | 原因 | 解决方案 |
|--------|--------|------|--------|
| 400 | Invalid mode: 'xxx' | 交易模式无效 | 模式必须为 'paper' 或 'live' |
| 400 | Invalid symbol format | 交易对格式错误 | 使用 'BASE/QUOTE' 格式，如 'BTC/USDT' |
| 400 | Timeframe not supported | 时间框架不支持 | 检查 `broker_config.json` 中的 `supported_timeframes` |
| 403 | Live trading is disabled | 实盘交易未启用 | 设置 `LIVE_TRADING_ENABLED=true` |
| 404 | Session not found | 会话ID不存在 | 检查会话是否已创建或已停止 |
| 500 | Failed to start session | 内部错误 | 查看日志获取详细错误信息 |
