## 策略开发与管理

本系统提供了一套完整的策略开发与管理解决方案，包括在线编辑器、内置策略模板库和严格的策略编写规范。用户可以通过前端界面创建和管理自己的交易策略，所有策略脚本都存储在`/backend/resources/strategy/`目录下。

### 在线编辑器与策略管理

系统通过前端组件`StrategyEditorPanel.jsx`和`StrategyMaintain.jsx`提供了一个功能丰富的在线代码编辑器，用户可以直接在浏览器中编写、修改和保存策略代码。策略文件以`.py`为扩展名，建议使用小写加下划线的命名方式（如`sma_cross.py`）。每个策略文件必须包含一个名为`UserStrategy`的类，并继承自`bt.Strategy`。

策略的创建、保存和加载通过后端API实现。`backtest_engine.py`中的`get_user_strategy_code`和`save_user_strategy_code`函数分别负责读取和写入策略代码。当用户在编辑器中点击保存时，前端会调用相应的API端点，将代码保存到服务器的策略目录中。

### 内置策略模板库

系统内置了一个丰富的策略模板库，位于`/backend/resources/strategy/templates/`目录下。这些模板涵盖了趋势跟踪、均值回归、统计套利和网格交易等多种交易策略，为用户提供了学习和参考的范例。

策略模板的管理和提供由`strategy_templates.py`模块负责。该模块定义了一个`StrategyTemplate`数据类，包含策略的ID、名称、分类、难度等级、适用市场和参数等元数据。通过`get_all_templates()`和`get_template_by_id()`函数，前端可以获取所有模板的列表或特定模板的详细信息（包括代码）。

用户可以通过前端的`TemplateLibrary`组件浏览和选择模板。当用户选择一个模板时，系统会将其代码加载到编辑器中，用户可以在此基础上进行修改和定制。

### 策略编写规范

策略的编写规范在`strategy.md`文件中有详细说明。核心要求包括：
- **命名规范**：策略文件使用小写加下划线命名，策略类必须命名为`UserStrategy`。
- **权限与责任**：策略逻辑、风险控制和发布决策由人工负责人负责。AI角色仅在明确授权下提供文档优化、代码审阅或辅助脚本，不得直接修改策略实现。
- **安全与合规**：禁止将真实交易密钥、账户信息或敏感配置写入仓库。回测参数、滑点和手续费需与真实环境一致或明确差异。
- **变更流程**：人工编写或审阅策略改动，确认核心逻辑、风控参数、交易品种与时间框架；通过Git提交，提交信息包含策略名、核心改动与验证结果。

## 策略回测系统

策略回测系统是验证交易策略有效性的核心工具。它通过`backtest_engine.py`模块实现，提供了一个完整的回测执行流程，从策略加载、数据获取到回测执行和结果生成。

### 回测执行流程

回测流程由`run_backtest`函数驱动，其执行流程如下：

1.  **策略加载**：系统首先通过`load_user_strategy`函数加载用户指定的策略。为了安全起见，代码在隔离的子进程中执行（通过`IsolatedSandbox`），以防止恶意代码对系统造成损害。如果沙箱模式设置为`soft`，则使用较不安全的`StrategySandbox`在主进程中执行。
2.  **数据获取**：通过`get_data`函数从`datasource.py`获取指定股票或交易对的历史数据。系统首先尝试从本地数据库加载数据，如果不存在，则通过`yfinance`库下载并缓存到数据库中。
3.  **回测执行**：使用`backtrader`框架的`Cerebro`引擎执行回测。引擎被配置为：
    - 添加用户策略（可传入自定义参数）
    - 添加历史数据
    - 设置初始资金、佣金和仓位大小
    - 添加多个分析器（夏普比率、最大回撤、收益率等）
4.  **结果生成**：回测完成后，系统收集所有分析器的指标，包括最终资产价值、夏普比率、最大回撤、年化收益率等。此外，系统还使用一个自定义的`TradeRecorder`分析器来记录每笔交易的详细信息（开仓/平仓价格、时间、盈亏等）。
5.  **图表生成**：如果指定了保存路径，系统会生成包含K线图和策略信号的图表并保存为图片。

### 完整的回测API调用示例

以下是一个完整的Python脚本示例，展示如何通过API调用执行回测：

```python
import requests
import json

# API端点
url = "http://localhost:8000/api/backtest"

# 回测参数
payload = {
    "ticker": "AAPL",
    "start_date": "2022-01-01",
    "end_date": "2023-12-31",
    "initial_cash": 100000.0,
    "commission": 0.0005,
    "stake": 100,
    "strategy_name": "sma_cross",
    "params": {
        "fast_period": 10,
        "slow_period": 30
    }
}

# 发送POST请求
headers = {'Content-Type': 'application/json'}
response = requests.post(url, data=json.dumps(payload), headers=headers)

# 处理响应
if response.status_code == 200:
    result = response.json()
    print(f"最终资产价值: {result['final_value']}")
    print(f"夏普比率: {result['sharpe']}")
    print(f"最大回撤: {result['drawdown']}%")
    print(f"总交易数: {result['trades']['total']['total']}")
else:
    print(f"回测失败: {response.text}")
```

## 实盘交易系统

实盘交易系统负责管理真实的交易会话，确保策略能够安全、可靠地在真实市场中执行。其核心由`live_engine.py`和`session_manager.py`两个模块协同工作。

### 交易会话生命周期管理

`session_manager.py`模块是整个实盘交易系统的核心，它通过单例模式的`SessionManager`类来管理所有交易会话的生命周期。每个会话由一个`TradingSession`数据类表示，包含会话ID、策略名称、交易对、状态、运行时对象（如`Cerebro`实例）等信息。

`SessionManager`提供了以下关键功能：
- **创建会话** (`create_session`)：初始化一个新的`TradingSession`对象，并将其注册到内部的会话字典中。
- **获取会话** (`get_session`)：根据会话ID查找并返回会话对象。
- **停止会话** (`stop_session`)：安全地停止一个正在运行的会话。它会先将会话状态设置为`STOPPING`，然后停止`CCXTStore`，并等待执行线程结束，最后更新状态为`STOPPED`。
- **会话列表** (`list_sessions`)：返回所有会话的列表，支持按状态过滤。

### `live_engine.py`与`session_manager.py`的协同工作

`live_engine.py`模块是实盘交易的入口，其`run_live`函数与`SessionManager`紧密协作：

1.  **启动会话**：当用户请求启动一个新会话时，`run_live`函数首先调用`session_manager.create_session()`创建一个会话对象。
2.  **初始化组件**：函数调用`_build_components`根据指定的交易所（如Binance）初始化`CCXTStore`、`CCXTBroker`和`CCXTData`等组件。
3.  **配置Cerebro**：创建`Cerebro`实例，添加策略、数据和分析器。
4.  **启动后台线程**：`run_live`函数在一个后台线程中调用`cerebro.run()`。这个线程会持续运行，直到被显式停止。
5.  **状态同步**：在后台线程中，会话的状态会随着`Cerebro`的运行而更新（如`RUNNING`、`ERROR`），并同步到`SessionManager`中。

当用户请求停止会话时，`live_engine.py`的`stop_live`函数会调用`session_manager.stop_session()`，后者负责执行安全的关闭流程。

### WebSocket实时监控

实时监控数据通过WebSocket推送，由`websocket_routes.py`模块提供支持。前端通过`/ws/live/{session_id}`端点连接到特定的交易会话。

`websocket_manager.py`负责管理所有WebSocket连接。当`live_engine.py`中的策略执行产生事件（如订单更新、持仓变化、P&L更新）时，它会通过`WebSocketManager`将这些事件以JSON格式推送给所有订阅了该会话的前端客户端。

WebSocket消息类型包括：
- `position`：持仓更新
- `order`：订单状态更新
- `pnl`：盈亏更新
- `trade`：交易执行
- `log`：日志消息
- `error`：错误信息
- `status`：会话状态变更

前端的`LiveTradingDashboard.jsx`组件订阅这些消息，并实时更新UI，为用户提供一个动态的交易监控面板。

## Walk-Forward参数优化

Walk-Forward参数优化是一种高级的回测技术，旨在检测策略的过拟合风险，并找到在样本外数据上表现稳健的参数。该功能由`walkforward_optimizer.py`模块实现。

### 算法逻辑

Walk-Forward分析的核心思想是将历史数据分为多个滚动或锚定的窗口，每个窗口包含一个训练期和一个测试期。

1.  **窗口生成**：`_generate_windows`函数根据`train_period_days`和`test_period_days`生成一系列时间窗口。对于滚动窗口，训练期和测试期一起向前移动；对于锚定窗口，训练期从固定起点开始并逐渐扩大。
2.  **参数优化**：在每个训练窗口上，`_optimize_on_train_window`函数会遍历`param_grid`中定义的所有参数组合，使用`_run_single_backtest`执行回测，并根据指定的优化指标（如夏普比率）选择表现最好的参数组合。
3.  **样本外验证**：使用在训练期选出的最佳参数，在紧随其后的测试期上进行回测，得到样本外的性能指标。
4.  **结果聚合**：重复上述过程，直到覆盖整个数据集。最终，系统会计算所有测试窗口的综合性能指标。

### 配置参数

`WalkForwardOptimizer`类接受以下关键配置参数：
- `strategy_name`：要优化的策略名称。
- `ticker`：交易对符号。
- `start_date`, `end_date`：优化的总体时间范围。
- `param_grid`：参数网格，一个字典，键为参数名，值为待测试的参数值列表。
- `train_period_days`, `test_period_days`：训练期和测试期的长度（天数）。
- `anchored`：布尔值，决定使用锚定窗口还是滚动窗口。
- `optimization_metric`：用于优化的指标，如`sharpe_ratio`、`total_return`或`profit_factor`。

### 避免过拟合

系统通过多种方式帮助用户避免过拟合：
- **过拟合检测指标**：`_calculate_overfitting_metrics`函数计算了多个关键指标来评估过拟合程度：
    - **平均退化率** (`avg_degradation_pct`)：训练期和测试期性能的平均下降百分比。如果该值过高（如>30%），表明存在严重过拟合。
    - **一致性得分** (`consistency_score`)：测试期性能在训练期性能20%范围内的窗口比例。得分越低，过拟合风险越高。
    - **相关系数** (`train_test_correlation`)：训练期和测试期性能的相关性。低相关性表明策略不稳定。
- **综合测试指标**：`_calculate_combined_test_metrics`函数计算了所有测试窗口的综合表现，这代表了策略在样本外的真实预期收益，是评估策略稳健性的最重要依据。
- **参数稳定性**：用户应观察不同窗口选出的最佳参数是否稳定。如果参数在不同窗口间剧烈变化，说明策略对参数高度敏感，容易过拟合。

## AI智能分析

AI智能分析功能利用大语言模型（LLM）的强大能力，对回测结果进行深度解读，并生成可操作的建议。该功能由`ai_routes.py`模块提供API支持。

### 调用OpenAI API进行分析

`ai_routes.py`中的`analyze_chart`端点是AI分析的核心。其工作流程如下：

1.  **接收请求**：前端通过`/ai_analyze`端点发送POST请求，携带用户的消息（`message`）、可选的图表图片（`file`）和模型选择（`model`）。
2.  **配置加载**：系统通过`ConfigManager`获取用户的OpenAI API密钥和基础URL。如果用户未配置，系统会回退到全局环境变量。
3.  **内容构建**：如果上传了图片，系统会将其编码为Base64字符串，并与文本消息一起构建成一个多模态消息列表。
4.  **API调用**：使用`AsyncOpenAI`客户端调用OpenAI的`chat.completions.create`接口。如果配置了代理，会通过`httpx.AsyncClient`进行代理连接。
5.  **返回结果**：将LLM生成的分析文本返回给前端。

### 生成可操作的建议

AI分析的核心价值在于将复杂的回测数据转化为人类可理解的洞察和行动指南。例如，当用户上传一张回测结果图并提问“这个策略表现如何，有什么改进建议？”时，AI可以：
- **总结表现**：概括策略的总体表现，如“该策略在2022-2023年期间实现了15%的总回报，夏普比率为1.2，表现稳健。”
- **识别问题**：指出潜在问题，如“策略在2022年11月市场剧烈波动期间出现了超过20%的最大回撤，风险控制有待加强。”
- **提出建议**：给出具体的、可操作的改进方案，如“建议引入ATR跟踪止损，将止损距离设置为2倍ATR，以更好地保护利润。同时，可以考虑在回撤超过10%时降低仓位50%。”
- **解释逻辑**：解释其建议背后的逻辑，增强用户的信任感。

前端的`AIInsight.jsx`组件集成了此功能，允许用户在查看回测结果时，一键调用AI助手进行分析，极大地提升了策略开发的效率和质量。
